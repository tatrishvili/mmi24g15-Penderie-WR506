## Implemented

See [CHILD_ACCOUNTS_DESIGN.md](../../CHILD_ACCOUNTS_DESIGN.md) for records, routes,
security boundaries and migration compatibility. Main entry points:

- `/foyer/enfants`: create/activate age-12–17 child username/password access,
  identify mother/father, reset/suspend, invite an existing verified second parent.
- `/connexion`: adult or child sign-in. Initial/reset child password expires after
  24 hours; first sign-in requires a different long password, followed by sign-in.
- `/enfant`: own items, private child-owned collections, parent-approved contacts
  and exact-preview publication requests. Parent management uses `?enfant=ID`.
- `/foyer/pieces/ajouter`: repeat room types, custom names, edit rooms, common or
  multiple profile assignments. Storage inherits the room's child access.
- `/articles/:id/visibilite`: owner-only, selected household people or the reviewed
  current household. A child requests approval. Recipients get read-only safe
  fields and photos, not notes/memories/QR/private locations or write permission.
- `/notifications`: recipient-scoped durable inbox, unread counts, pagination,
  independent mark-read, accept/decline and child decisions.
- `/partages-famille`: approved limited child publications, including for named
  adult relatives who receive no inventory-management permission.

ChildAccount is a separate security principal. Parent authority is an explicit
GuardianLink, including acceptance/expiry for the additional parent. Adults cannot
switch into another adult's identity. Child sessions cannot recover the parent
account, household/security controls, adult social graph, selling or lending.
Password/access/parent changes revoke child sessions, including trusted-device
selected-child mode. Invalid selected profiles fail closed and the UI signs out.

FamilyAccess distinguishes management from reviewed viewing. Lists filter access
before pagination; room filters cannot disclose another person's hidden location.
Room access changes preserve objects while redacting restricted child paths on
list/detail/QR/update responses. Every item/photo mutation independently checks
management authority.

Approval freezes safe fields/photos, recipients and source versions. Parent
transactions and optimistic versions reject stale/duplicate approval. Source
changes, archive/Personal, revoked parents/contacts and withdrawals block reads,
including photo endpoints (`private, no-store`). Re-adding a contact cannot restore
old publications because connection proofs are frozen too.

Observed after Docker Desktop/PC restart:

- nginx failed before starting: its saved WSL config file bind mount appeared as
  a directory (`OCI runtime ... error mounting ... not a directory`).
- API ran with an empty backend mount and was unhealthy; frontend could not reach nginx.

`fix/wsl-restart-recovery` commit `175f89a` is pushed separately. nginx now builds

`~/.config/systemd/user/penderie-wsl-recovery.{service,timer}` and lingering enabled.

empty/config mount failures while leaving healthy or deliberately stopped stacks
alone. Definitions/tests are in `docker/`; it does not start WSL/Docker Desktop
from Windows. A full PC reboot was not performed. Seven recovery decision tests,
container recreation/restart and health/proxy 200 checks passed.
